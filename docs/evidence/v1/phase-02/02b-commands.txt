WHAT DID NOT WORK, IN ORDER
--------------------------------------------------------------------------------

A. `@mode` as a literal constant. Elixir 1.20's type checker proved every
   `Schema.mode() == :strict` branch dead and warned on it, and this package
   compiles with warnings_as_errors, so the transition branches could not be
   written at all. Resolved by computing the mode through `mode/1` over the
   version string, which the compiler cannot fold. The same change is what makes
   both halves testable without depending on the package version.

B. `Schema.defaults/1` was called from Config's module body before it existed:
   an UndefinedFunctionError at compile time, fixed by adding the function.

C. A `@typedoc` on a private type (`@typep resolution`) warns and is therefore an
   error here. Replaced with a comment.

D. `assert_raise KeyError, fn -> Map.fetch!(Config.defaults(), :never_declared) end`
   produced a type warning ("this function will always raise") because the
   compiler can see the whole map. Replaced with an assertion on the key set.

E. The two test failures in (8) and the one in (9), described there.

F. The credo consistency issue in (14), described there.

G. Four ex_doc "documentation references X but it is hidden/undefined" warnings,
   three of them this unit's. Fixed by rewording; see (17).
