# 10a: the dash scan, before and after

`open-findings.md` X88. Both columns come from **one** detector
(`tmp/v1/10a_dashcount.py`) run twice: once over a `git archive` of each
package's HEAD, and once over the working tree this unit leaves. A sweep whose
before and after come from two versions of one detector measures the detector,
so the before tree is materialised rather than remembered.

A second, independent detector agrees with the after column: the in-suite guard
(`AuroraMeter.HouseStyleTest` and `AuroraMeter.Pro.HouseStyleTest`) reads the
Elixir **AST** rather than the file text, and its run is in `10a-doc-test.log`.
The two disagreed once, and the disagreement is recorded in `10a-report.md`
section 4: the Python detector measured indentation against the file while the
AST detector measured it against the dedented heredoc, so one dash in a doc
string's list item was classified as code by the first and prose by the second.
The AST detector was right, the Python one was corrected, and both columns here
are from the corrected version.

Classification, and it is the whole point of the row: a dash inside a fenced
block, an inline code span, a URL or a `#` comment is not prose. X88 says so.
